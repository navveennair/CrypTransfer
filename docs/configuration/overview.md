# Configuration Overview

This document describes the configuration required to build and run CrypTransfer, a Flutter
(Material 3) application backed by Firebase (Auth, Firestore, Storage).

## Firebase Setup

CrypTransfer initializes Firebase at app startup via `lib/main.dart`:

```dart
await Firebase.initializeApp(
  options: DefaultFirebaseOptions.currentPlatform,
);
```

`DefaultFirebaseOptions` is defined in `lib/firebase_options.dart`, a file generated by the
FlutterFire CLI (`flutterfire configure`). It provides per-platform `FirebaseOptions` (API key,
app ID, project ID, storage bucket, etc.) for Android, iOS, macOS, Web, and Windows.

### Firestore Security Rules

Firestore access control is defined in `firestore.rules` at the project root and deployed via:

```bash
firebase deploy --only firestore:rules
```

Key rule helpers:
- `isAdmin()` — checks `users/{uid}.isAdmin == true`
- `isAuthenticated()` — checks `request.auth != null`
- `isOwner(uid)` — checks `request.auth.uid == uid`

These gate access to the `users`, `notifications`, `audit_logs`, `handshakes`, `transfers`, and
related collections described in the project's data model.

### Release Signing (`android/key.properties`)

Release builds are signed using credentials loaded from `android/key.properties`, which is
**git-ignored** and must be created manually on each machine that produces signed release builds.

`android/app/build.gradle.kts` reads this file:

```kotlin
val keystorePropertiesFile = rootProject.file("key.properties")
val keystoreProperties = Properties().apply {
    if (keystorePropertiesFile.exists()) load(FileInputStream(keystorePropertiesFile))
}
```

If the file is **absent**, the release build type falls back to debug signing automatically, so
`flutter build apk --release` / `flutter run --release` still work without it on a dev machine.

To set up release signing, create `android/key.properties`:

```properties
storeFile=../my-release-key.jks
storePassword=<password>
keyAlias=<alias>
keyPassword=<password>
```

`storeFile` is resolved relative to the `android/app/` directory (`file(...)` in Gradle resolves
relative to the module's project directory).

### R8 Minification & ProGuard

The release build type enables R8 minification and resource shrinking:

```kotlin
buildTypes {
    release {
        isMinifyEnabled = true
        isShrinkResources = true
        proguardFiles(
            getDefaultProguardFile("proguard-android-optimize.txt"),
            "proguard-rules.pro",
        )
        ...
    }
}
```

Keep rules for the Flutter engine, Firebase, and PointyCastle (cryptography library) are defined
in `android/app/proguard-rules.pro` to prevent R8 from stripping classes required by reflection
or JNI.

## Feature Flags

There is no dedicated feature-flag system (e.g. Remote Config, LaunchDarkly) in this project.
The closest analog is the **`isAdmin`** boolean field on each `users/{uid}` Firestore document
(see `lib/data/models/user_model.dart`), which gates access to the Admin Dashboard
(`lib/presentation/admin/`) via `AdminGuard` (`lib/presentation/admin/admin_guard.dart`). This
flag is set per-user directly in Firestore and defaults to `false` for new accounts
(`auth_repository.dart`).
