KEY POINTS
══════════

1. ENTRY: Both "Send" and "Receive" routes start at _RolePickerSheet

2. BIFURCATION: The role is determined by the `isSender: true/false` parameter
   to assignTransferRole() — this is the ONLY decision point

3. SEPARATE SCREENS: SenderScreen and ReceiverScreen are completely independent:
   • Different files
   • Different state management
   • Different service initialization
   • Different UI layouts
   • Different stream listeners

4. NO SHARED STEPPER: There is NO unified "TransferStepperScreen(role: ...)"
   that dynamically branches based on configuration

5. SUB-SCREENS: Both paths eventually push to screen-specific transfer screens:
   • Sender → TransferProgressScreen (upload tracking)
   • Receiver → ReceiverTransferScreen (download waiting)

6. SERVICES: Each screen independently initializes its required services.
   The SessionManager is passed from ReceiverScreen to its children for
   kill-switch propagation.

7. FIRESTORE: The handshakes/{docId} document stores the role assignment
   and is referenced by both screens via the handshakeDocId parameter.
