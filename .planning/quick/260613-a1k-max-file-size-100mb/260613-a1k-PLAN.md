## Task

Add a file size guard in `_pickFile()` so that any file over 100 MB is rejected immediately
after selection, before encryption or upload begins.

## Why 100 MB

`FirebaseConstants.maxDownloadBytes = 100 * 1024 * 1024` is the hard cap passed to
`ref.getData()` on the receiver side. Files exceeding this would silently fail at download
with no user-facing error. The sender-side guard surfaces this constraint at the right moment.

## Changes

### Task 1 — Add import + size guard in `_pickFile()`

**File:** `lib/presentation/sender/sender_screen.dart`

- Import `firebase_constants.dart` (single source of truth for the 100 MB constant)
- After `final file = result.files.first;`, check `file.size > FirebaseConstants.maxDownloadBytes`
- Show a red SnackBar with the file's actual size and the 100 MB limit
- `return` early — nothing else in `_pickFile()` executes for oversized files

## Verification

- `flutter analyze lib/presentation/sender/sender_screen.dart` → No issues
- Guard uses `FirebaseConstants.maxDownloadBytes` (not a magic number) — stays in sync if limit changes
- Files under 100 MB: unaffected, normal flow continues
- Files over 100 MB: error SnackBar shown, file not attached, encryption/upload never start
