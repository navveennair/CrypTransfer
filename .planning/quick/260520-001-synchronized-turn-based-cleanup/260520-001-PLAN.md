# Quick Task 260520-001: Synchronized Turn-Based Cleanup Protocol

## Context

Current flow: Receiver runs all cleanup steps unilaterally, sender only detects doc deletion.

New protocol (4 turns):
1. **Turn 1 — Receiver Initiates**: Receiver taps "End Session" → sets `status:'cleanup_initiated'` on transfer doc → shows "Waiting for Sender to securely erase cryptographic keys..."
2. **Turn 2 — Sender Wipes AES Key**: Sender stream detects `cleanup_initiated` → sets `encryptedAESKey:''` + `senderCleanedUp:true` on Firestore → wipes AES key from RAM → shows "Keys destroyed. Waiting for Receiver to terminate session..."
3. **Turn 3 — Receiver Confirms and Burns**: Receiver stream detects `senderCleanedUp==true` → verifies `encryptedAESKey` is empty → runs full cleanup (audit log, storage delete, transfer doc + handshake WriteBatch, RSA close)
4. **Turn 4 — Simultaneous Redirect**: Receiver → pushAndRemoveUntil HomeScreen; Sender detects doc deletion (snapshot.exists==false) → navigates to SenderSessionEndedScreen as before

## Files Changed

- `lib/data/models/transfer_model.dart` — add `senderCleanedUp` field
- `lib/data/repositories/transfer_repository.dart` — add `initiateCleanup()` + `senderWipeAESKey()`
- `lib/presentation/sender/transfer_progress_screen.dart` — handle `cleanup_initiated` in stream listener
- `lib/presentation/receiver/receiver_end_session_screen.dart` — split End Session into Turn 1 trigger + Turn 3 final cleanup
