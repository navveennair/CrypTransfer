<decisions_made>

- Removed `SystemController`, `RSAKeys`, `File`, `TLSChannel`, `Database` classes
  entirely — none exist in the codebase. The app is a serverless Flutter client
  using Firebase SDK directly via a Repository pattern (`AuthRepository`,
  `KeyRepository`, `HandshakeRepository`, `TransferRepository`,
  `CleanupRepository`).
- Private RSA key is modeled as device-only (`FlutterSecureStorage`), never an
  attribute on `User` or any Firestore-backed entity — this matches the
  kill-switch / zero-remanence security design and was a factual error in the
  original diagram.
- Added missing `iv: String` field to `TransferSession` (AES-256-GCM requires the
  96-bit IV alongside the RSA-wrapped AES key).
- Renamed `encryptedFilePath` → `encryptedFileUrl` (Firebase Storage download URL,
  not a local path).
- Added previously-missing classes that are core to the real architecture:
  `Handshake` (replaces RSAKeys — models the `handshakes` collection),
  `ConnectionProposal` (models `neutral_handshakes`), `NotificationModel`,
  `SessionManager` (kill-switch state machine), `SecurityLifecycleMixin`
  (zero-wipe buffer registry), `TransferService` (64KB chunked file I/O),
  `EncryptionService` marked `<<static>>`/stateless.
- **Mermaid is now the preferred diagram format for this thesis work** (sequence,
  activity, ERD, class diagrams) — user explicitly asked to switch from PlantUML
  to Mermaid after the first version was produced.
</decisions_made>
