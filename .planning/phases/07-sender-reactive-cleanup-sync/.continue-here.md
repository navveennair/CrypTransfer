# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Firestore listener timing — subscribe ONLY after the doc exists. `_startTransferListener()` must never be called from `initState()` for a doc that is created asynchronously later. Always call it after the `.set()` / `.add()` that creates the doc completes.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Listener-before-doc | Subscribing to a Firestore doc stream before the doc exists → security rule evaluates `resource.data.field` as null → permission denied → stream silently cancelled with no error thrown | blocking | In `_startUpload()`: call `_startTransferListener()` only in the `.then()` / after `await` that creates the doc. Never in `initState()` for async-created docs. |
| Scale from corner | `Matrix4.diagonal3Values(s, s, 1.0)` without `transformAlignment: Alignment.center` scales from top-left (0,0) origin, causing visible jitter | advisory | Always pair with `transformAlignment: Alignment.center` on every `AnimatedContainer` that uses a scale transform. |
| TOCTOU on mutual-accept | Reading a Firestore doc before a WriteBatch allows it to change between read and write → accepted mutual proposal gets only one direction updated | advisory | Use `runTransaction` (not WriteBatch) when read + write must be atomic. |
| Single-doc disconnect | `cancelProposal(docId)` deletes only one directional doc; mutual-accept creates two `connected` docs (`A_B` AND `B_A`) | advisory | Use `disconnectFromUser(partnerUid)` WriteBatch that deletes both deterministic doc IDs. |

<decisions_made>
