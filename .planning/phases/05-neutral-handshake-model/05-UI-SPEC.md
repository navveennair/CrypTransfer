| Role | Value | Usage |
|------|-------|-------|

**Outcome banner (D-08) specific:** Same color as existing `_NotifBanner` (indigo tint) — proposer outcome is a standard notification event, not a new action; visual parity with system notifications.

## Interaction Contracts

### HomeScreen Layout (D-04, D-05)

**Scroll order (top to bottom):**
1. Welcome banner (existing — unchanged)
2. `SizedBox(height: 24)`
3. Active Connections section header: "Active Connections" (14sp, w600, `cs.onSurfaceVariant`) + "Add New Connection" icon-text button (trailing, accent color)
4. `SizedBox(height: 12)`
5. `StreamBuilder` → Active Connection rows (status=connected) + Pending rows with amber Pending badge (status=pending, proposerId=currentUser) — both rendered in the same `Column`, pending rows below connected rows
6. If both connected and pending streams empty → `_EmptyConnectionsPrompt`
7. `SizedBox(height: 24)`
8. Pending Requests section (only rendered if `streamIncomingPending()` is non-empty — `SizedBox.shrink()` otherwise)
9. `SizedBox(height: 32)`
10. Recent Transfers section (existing — unchanged)

**Retired:** The "I am a Sender" and "I am a Receiver" `GlassButton` widgets and the "Actions" section header are removed entirely.

### `_ProposalBanner` Interaction (D-02, D-03)

- Renders as `OverlayEntry` positioned at `MediaQuery.of(context).padding.top + 8` (matches `_NotifBanner` exactly)
- Icon: `Icons.person_add_rounded` in deepPurple circle container (replaces `Icons.notifications_active_rounded`)
- Message: "@proposerUsername wants to connect"
- Action row: Accept (`TextButton` with `Colors.green`, "Accept") + Reject (`TextButton` with `cs.error`, "Reject") — right-aligned after the Dismiss X button
- Accept tap: calls `onAccept` callback → calls `HandshakeRepository.acceptProposal()` → banner dismisses → partner UID appears in Active Connections section
- Reject tap: calls `onReject` callback → calls `HandshakeRepository.rejectProposal()` → banner dismisses → proposal disappears from Pending Requests section
- Dismiss X tap (no action): calls `onDismiss` → banner removes; proposal remains in `pending` state; re-surfaces in Pending Requests section (D-03)
- 5-second auto-dismiss: same `Timer(Duration(seconds: 5), onDismiss)` pattern — auto-dismiss with no action taken (same as X tap behavior)

### Active Connection Row Interaction (D-11)

- Full row is tappable (`InkWell` wrapping `GlassContainer`)
- Tap on a **Connected** row → opens `_RolePickerSheet` bottom sheet
- Tap on a **Pending** row (proposer's own) → no navigation; shows SnackBar: "Waiting for @username to respond" — tap area blocked for session entry until status=connected
- Cancel icon button (trailing, Pending rows only): `IconButton(icon: Icon(Icons.cancel_outlined), color: Colors.amber.shade400)` → triggers `HandshakeRepository.cancelProposal()` with confirmation; see Destructive Actions section

### `_RolePickerSheet` Tiles (D-13, D-14)

- Bottom sheet height: `isScrollControlled: true` + `useSafeArea: true` — sheet takes natural content height
- Two tiles stacked vertically with 16px gap:
  - **[Send File]** tile: `Icons.upload_file_rounded` (accent color) + "Send File" (20sp w600) + "You encrypt and transmit" (12sp w400 secondary) + `Icons.chevron_right_rounded` trailing
  - **[Receive File]** tile: `Icons.download_rounded` (cs.secondary) + "Receive File" (20sp w600) + "You decrypt and save" (12sp w400 secondary) + `Icons.chevron_right_rounded` trailing
- Each tile is a `GlassContainer` with `borderRadius: 16`, `padding: EdgeInsets.all(20)`, wrapped in `InkWell`
- Tile minimum height: 72px
- Sheet padding: 24px horizontal, 16px bottom (plus safe area)

### Cancel Proposal Confirmation (D-10, Destructive)

- **No full dialog** — use an inline `showModalBottomSheet` with two options: "Cancel Request" (destructive red) + "Keep Waiting" (ghost)
- Confirmation copy: "Cancel request to @username? They won't be notified." + [Cancel Request] (red) / [Keep Waiting] (dismiss)
- On confirm: `HandshakeRepository.cancelProposal(docId)` → pending row disappears reactively from stream

### Outcome Banner Animation (D-08, D-09)

- Acceptance outcome: `_NotifBanner` (standard indigo, existing component) — message: "Connection accepted by @username" — 5-second auto-dismiss
- Rejection outcome: `_NotifBanner` (standard indigo) — message: "Connection request declined" — 5-second auto-dismiss
- After rejection banner dismisses: the Pending row (proposer's outgoing) disappears reactively via Firestore stream (`status=rejected` → row no longer in `streamOutgoingPending()` results) — no animation, silent removal (D-09)

## State Matrix

Each new component must handle these states explicitly.

### Active Connection Row

| State | Visual |
|-------|--------|
| Connected | Green `SecurityBadge`-style badge, row fully tappable, no cancel button |
| Pending (own outgoing) | Amber "Pending" badge, row tap shows SnackBar (not navigable), amber cancel `IconButton` trailing |
| Loading (stream pending) | `CircularProgressIndicator` centered in section area |
| Error | Inline error text at section level: "Couldn't load connections." with retry link |

### Pending Request Row (partner's inbound)

| State | Visual |
|-------|--------|
| Idle | Accept (green CrypButton) + Decline (ghost TextButton), UserAvatar, @username |
| Accepting in-flight | Accept button shows `CircularProgressIndicator` (replaces label), both buttons disabled |
| Rejecting in-flight | Decline button shows spinner, both buttons disabled |
| Success | Row disappears reactively via stream |
| Error | SnackBar: "Couldn't accept/decline request. Try again." Row remains |

### `_ProposalBanner` (OverlayEntry)

| State | Visual |
|-------|--------|

## Discretion Resolutions (Claude's Decisions)

These were left to Claude's discretion in CONTEXT.md. Resolved here as binding contract.

### Simultaneous Mutual Proposals
**Decision:** When A proposes to B and B simultaneously proposes to A, both docs exist (`A_B` pending + `B_A` pending). Display both as a **single merged row** in Active Connections, deduplicating by partnerUid. When either party accepts, both docs are updated to `connected` via `WriteBatch`. The row appearance does not change between single-proposal and mutual-proposal cases — the user sees one row per partner regardless.

### Cancel Button Placement (Pending Row)
**Decision:** **Trailing icon button** — `IconButton(icon: Icon(Icons.cancel_outlined), color: Colors.amber.shade400, onPressed: _showCancelConfirmation)`. Reasoning: swipe-to-dismiss is ambiguous on a list that is not a `Dismissible`; a context menu (`PopupMenuButton`) adds an extra tap and hides the action; a visible icon communicates withdrawability at a glance. The amber color matches the Pending badge color, creating a visual group.

### Firestore Doc ID Scheme
**Decision:** Deterministic `${proposerId}_${partnerId}` — mirrors the `publishRSAPublicKey` pattern in `key_repository.dart`. Idempotent re-proposals produce no duplicates. **Source:** RESEARCH.md Pattern 1, `key_repository.dart` [VERIFIED]

## Implementation Notes for Executor

1. **`_ProposalBanner` is a new private class in `home_screen.dart`** — do NOT modify `_NotifBanner`. The two classes coexist. `_NotifBanner` continues to handle `rsa_key_received` and `file_received` notification types; `_ProposalBanner` handles `neutral_handshake` proposal events.

2. **Section header pattern** — use the existing `Row(children: [Icon(...), SizedBox(width: 8), Text('Section Name', style: GoogleFonts.poppins(fontWeight: FontWeight.w600, fontSize: 14)), Spacer(), ...trailing action...])` pattern exactly as used for the "Recent Transfers" header [VERIFIED: home_screen.dart lines 181-201].

3. **HomeScreen body uses `SingleChildScrollView` with `Column`** — the new Active Connections and Pending Requests sections slot in between the Welcome banner and Recent Transfers sections. Maintain `padding: EdgeInsets.symmetric(horizontal: 20, vertical: 10)` on the outer scroll view.

4. **`_RolePickerSheet` bottom sheet** — use `showModalBottomSheet` with `isScrollControlled: true`, `useSafeArea: true`, `backgroundColor: Colors.transparent`. Top child is `BottomSheetHandle`, then 16px padding, then the two tiles. Match `receiver_screen.dart` lines 276-289 exactly for the outer scaffold [VERIFIED].

5. **Pre-fill sequencing** — ReceiverScreen pre-fill MUST call `_onSenderSelected()` inside a `.then()` chained to `_checkKeyStatus()`. Do not call it directly in `initState()`. See RESEARCH.md Pitfall 5.

6. **Listener startup** — new `_startHandshakeListener()` in HomeScreen MUST be wrapped in `WidgetsBinding.instance.addPostFrameCallback((_) => ...)` alongside the existing `_startNotifListener()`. See RESEARCH.md Pitfall 1.

7. **DocChange deduplication** — use `_lastSeenProposalId` field (String?) in `_HomeScreenState` to prevent repeat banners on stream re-subscribe. Mirror the existing `_lastBannerDocId` pattern [VERIFIED: home_screen.dart line 48].
