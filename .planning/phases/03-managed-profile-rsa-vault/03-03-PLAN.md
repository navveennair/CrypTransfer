// NOTE: method is STATIC so the vault screen can call AuthRepository.computeFingerprint()
// without needing to instantiate AuthRepository or import its private internals.
static String computeFingerprint(String publicKeyJson) {
  final bytes = Uint8List.fromList(utf8.encode(publicKeyJson));
  final digest = SHA256Digest();
  final hash = digest.process(bytes);
  return hash.map((b) => b.toRadixString(16).padLeft(2, '0')).join();
  // returns full 64-char hex string; caller displays first 16 chars as human fingerprint
}

    **Add regenerateKeyPair():**
    ```dart
    /// Regenerates the RSA-2048 keypair.
    /// Writes new private key to FlutterSecureStorage, updates publicKey in Firestore,
    /// and appends an immutable audit document to rsa_key_manager subcollection.
    /// Uses a 3-doc WriteBatch: publicKey update + audit log + keyVaultCreatedAt (D-14).
    Future<void> regenerateKeyPair(String uid) async {
      final pair = await compute(_generateKeyPairIsolate, null);
      final pubKey = pair.publicKey as RSAPublicKey;
      final privKey = pair.privateKey as RSAPrivateKey;

      final pubKeyJson = EncryptionService.encodePublicKey(pubKey);
      final privKeyJson = EncryptionService.encodePrivateKey(privKey);
      final fingerprint = computeFingerprint(pubKeyJson);

      // Write new private key first — old key is superseded immediately.
      await _secure.write(
        key: FirebaseConstants.privateKeyStorageKey,
        value: privKeyJson,
      );

      final userRef = _db.collection(FirebaseConstants.users).doc(uid);
      final auditRef = userRef.collection(FirebaseConstants.rsaKeyManager).doc();
      final prefsRef = userRef.collection(FirebaseConstants.profile).doc('preferences');
      final batch = _db.batch();
      batch.update(userRef, {'publicKey': pubKeyJson});
      batch.set(auditRef, {
        'action': 'regenerated',
        'timestamp': FieldValue.serverTimestamp(),
        'publicKeyHash': fingerprint,
        'deviceInfo': '${Platform.operatingSystem} ${Platform.operatingSystemVersion}',
      });
      batch.set(prefsRef, {'keyVaultCreatedAt': FieldValue.serverTimestamp()},
          SetOptions(merge: true)); // D-14: stamp regeneration time; merge preserves other prefs
      await batch.commit();
    }
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AuthRepository → FlutterSecureStorage | Private key written/deleted here; platform keystore boundary |
| AuthRepository → Firestore | WriteBatch crosses this; 3-doc commit (publicKey + audit + keyVaultCreatedAt) for regenerate |
| compute() isolate → main isolate | RSA key material returned from isolate; private key JSON registered for zero-wipe if held as buffer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | Information Disclosure | Partial key rotation | mitigate | regenerateKeyPair() writes new private key to SecureStorage FIRST (before Firestore batch). Old key is superseded before public key updates. If batch.commit() fails, the secure storage has the new key but Firestore still has old public key — inconsistent state, but no key material leaked. Vault screen can retry. |
| T-03-03-02 | Tampering | audit log audit_doc immutability | mitigate | Firestore `update: false` rule (added in Plan 05) enforces server-side. Client-side: no update() call is ever made on audit docs — only add()/set() with auto-generated IDs. |
| T-03-03-03 | Information Disclosure | SHA-256 fingerprint reveals key material | accept | SHA-256 of public key JSON is safe to store: public keys are by definition public; the fingerprint reveals nothing about the private key. Full 64-char hash stored; 16-char display truncation is for UX only. |
| T-03-03-04 | Information Disclosure | deviceInfo leaks OS version | accept | Platform.operatingSystem + operatingSystemVersion is non-sensitive device metadata. Standard practice for audit logs. |
| T-03-03-05 | Denial of Service | updateLastVaultAccess fails for pre-Phase-03 users | mitigate | SetOptions(merge: true) creates doc if missing — lazy init path. Error caught and rethrown as NetworkException; UI shows snackbar, vault still opens. |
</threat_model>
