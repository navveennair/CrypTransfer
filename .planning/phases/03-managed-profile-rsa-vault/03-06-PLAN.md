<objective>
Close the two gaps that block all Key Vault mutation ops in Phase 03.

Gap 1 (primary blocker — all three tests 3/4/5 failing): The
rsa_key_manager and profile subcollection rules were written in 03-05 but
never pushed to the live Firebase project. Every Generate / Regenerate /
Delete call from the app returns PERMISSION_DENIED because the emulator
rules (or outdated production rules) do not include the new subcollections.
Fix: deploy firestore.rules.

Gap 2 (secondary desync risk): deleteKeyPair() calls _secure.delete()
at line 297 before batch.commit() at line 309. If the batch fails after
the secure-storage wipe, the device loses the private key while Firestore
still holds the public key — a permanently inconsistent state. Fix: move
_secure.delete() to after a successful batch.commit().

Purpose: Unblock UAT tests 3, 4, and 5 and eliminate the key-desync
failure mode from deleteKeyPair().

Output: Deployed firestore.rules + corrected auth_repository.dart.
</objective>
