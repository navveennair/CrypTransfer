CRITICAL rules:
1. Do NOT use `async`/`await` inside `onPopInvokedWithResult` — use `.then()` only (framework ignores returned Futures from async void callbacks).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User → ReceiverScreen back gesture | Hardware back / swipe gesture crosses the PopScope boundary; previously untrusted (no confirmation) |
| ReceiverScreen → EncryptionService | wipeSession() → stateStream → EncryptionService.closeReceiverSession() — reactive cleanup chain |
| User → ReceiverScreen Step 1 (while mailbox open) | RSA key regeneration while session active would invalidate the handshake silently |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | PopScope.canPop (receiver_screen.dart) | mitigate | Change canPop to `_isReadyToReceive ? false : (_handshakeDocId == null)`; session locked path shows SnackBar; confirmation path calls wipeSession before pop — key material is always wiped before leaving the screen |
| T-09-03 | Tampering | ReceiverScreen Step 1 StepCard | mitigate | Wrap Step 1 in IgnorePointer(ignoring: _isReadyToReceive) — prevents RSA key regeneration while mailbox is open, which would invalidate the active handshake and leave stale key material in Firestore |
| T-09-04 | Elevation of Privilege | AppBar settings IconButton (→ RsaKeyManagerScreen) | mitigate | Set onPressed to null when _isReadyToReceive — prevents navigation to key manager (which can regenerate RSA keys) while a session is active |
</threat_model>
