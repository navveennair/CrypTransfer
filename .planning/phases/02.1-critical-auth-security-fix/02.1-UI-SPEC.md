# Phase 02.1 — UI Design Contract

> Visual and interaction contract for the Identity & Networking upgrade.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Flutter Material 3 + custom AppTheme) |
| Preset | not applicable |
| Component library | Flutter Material 3 widgets + custom GlassContainer / GlassButton / CrypButton from `shared_widgets.dart` |
| Icon library | Material Icons rounded variant (`Icons.*_rounded` / `Icons.*_outlined`) |
| Font | Poppins (headings, buttons, labels via `GoogleFonts.poppins`) + Inter (body via `GoogleFonts.inter`) |

Source: `lib/app_theme.dart` — AppTheme class; `lib/presentation/widgets/shared_widgets.dart` — component inventory.

## Spacing Scale

All values are multiples of 4. Matches the existing spacing conventions observed across `login_screen.dart`, `shared_widgets.dart`, and `sidebar_drawer.dart`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside GlassButton (`SizedBox(width: 8)`); inline badge padding |
| sm | 8px | Compact element spacing; SnackBar internal padding; SecurityBadge padding |
| md | 16px | Default field-to-field spacing; card internal horizontal padding |
| lg | 24px | GlassContainer internal padding (`padding: EdgeInsets.all(24)`); section gaps |
| xl | 32px | Between major form card and register link row |
| 2xl | 48px | Between header block (logo + title) and form card |
| 3xl | 64px | Page-level vertical breathing room at scroll extremes |

Exceptions:
- Touch target minimum for icon buttons (visibility toggle, disconnect): 44px × 44px — enforced by Material `IconButton` default tap target.
- `CrypButton` default height: 52px face + 4px depth = 56px total stack height. This is the system primary action height and must not be reduced.
- `DrawerHeader` height: 80px (Flutter default) — do not override; matches sidebar_drawer.dart.
- Avatar radius in `ConnectionsScreen` friend rows: 20px radius (40px diameter) — aligns with `UserAvatar` widget defaults observed in `shared_widgets.dart`.
- `_OrDivider` intrinsic height 20px = 1px divider line + 8px vertical padding top + 8px vertical padding bottom + ~3px text line-height — not a layout spacing token.

## Typography

Source: `lib/app_theme.dart` — two-font system (Poppins + Inter). Codebase uses a consistent 4-size scale observed across all screens.

| Role | Size | Weight | Line Height | Font | Usage |
|------|------|--------|-------------|------|-------|
| Display | 32px | SemiBold (600) | 1.2 | Poppins | App name "CrypTransfer" on Login/Register header |
| Heading | 20px | SemiBold (600) | 1.3 | Poppins | Section headers inside GlassContainer ("Sign In", "Create Account", "My Connections"); AppBar title |
| Label | 15px | SemiBold (600) | 1.4 | Poppins | Button text in GlassButton and CrypButton; step card titles |
| Body | 14px | Regular (400) | 1.5 | Inter | Form field hint/label text; body copy in dialogs; friend row username; error messages below form fields; secondary metadata (email in drawer header, "Friend" status tag) |

Do not introduce additional sizes. Validation error text is always 14px `cs.error` color — never 13px or 12px. Do not use `FontWeight.bold` (700) anywhere in this phase; use `FontWeight.w600` for all strong text.

## Surface 2: Register Screen Updates

**File:** `lib/presentation/auth/register_screen.dart`

The register screen already uses live per-field validation with the `_FS` enum state machine. The changes are:

### Password Strength Upgrade
Current validator: `v.length >= 6`
New validator: `v.length >= 8 AND RegExp(r'(?=.*[a-zA-Z])(?=.*\d)').hasMatch(v)`

Error messages (one shown at a time, in priority order):
1. `'Password is required'` — when empty
2. `'Minimum 8 characters'` — when length < 8
3. `'Must contain a letter and a digit'` — when regex fails

Error text style: 14px, `cs.error`, weight 400. Shown below the field inline (existing `_FS`-driven display pattern — do not change structure).

### Password Confirm Field
Validator continues to compare against `_passwordController.text`. Error: `'Passwords do not match'`.

### Google Sign-In Button
Same placement pattern as Login screen:
- Below the primary "Register" CrypButton
- Separated by `_OrDivider`
- Full width

### No Other Layout Changes
The register screen's multi-field layout, decorative background, and validation state machine are retained as-is.

## Surface 4: Google Sign-In Button Variant

**Context:** Appears on both Login and Register screens. Implemented as a `GlassButton` with Google branding.

### Specification

```dart
GlassButton(
  icon: Image.asset(
    'assets/images/google_logo.png',
    height: 20,
    width: 20,
  ),
  label: const Text('Continue with Google'),
  color: Colors.white,       // white tint — glass fill = white 15% alpha
  onPressed: _isLoading ? null : _signInWithGoogle,
)
```

- `color: Colors.white` produces `glassBg = Colors.white.withValues(alpha: 0.15)` fill and `Colors.white.withValues(alpha: 0.3)` border — distinguishes the button visually from the primary blue CTA above it.
- Label text color: `Colors.white` (inherited from `GlassButton.DefaultTextStyle`). Weight: SemiBold 600, 15px Poppins.
- The Google logo asset must be placed at `assets/images/google_logo.png`. It is the official Google "G" logo SVG rasterized at 40×40px minimum. Do not use `Icons.g_mobiledata` — it does not satisfy Google Sign-In branding guidelines.
- When `_isLoading` is true: `onPressed: null` makes `GlassButton` render at 50% opacity (existing `Opacity` wrapper).

### _OrDivider Widget (new, shared)

Placed between the primary CTA and the Google button on both auth screens.

```
Row
  Expanded > Divider (color: darkBorder, thickness: 1)
  Padding(horizontal: 8) > Text "or" — Inter 14px textSecondary weight 400
  Expanded > Divider (color: darkBorder, thickness: 1)
```

Height: 20px total (intrinsic — 1px divider + 8px vertical padding top + 8px vertical padding bottom + ~3px text line-height; not a layout spacing token). No additional vertical spacing beyond `SizedBox(height: 16)` above and below it.

## Surface 5: Theme Onboarding Overlay

**File:** `lib/presentation/widgets/theme_onboarding_dialog.dart` (new)

### Trigger Conditions
- Shown ONLY when `prefs.getBool('theme_selected') ?? false == false`
- Called via `await showDialog(barrierDismissible: false, ...)` BEFORE `Navigator.pushAndRemoveUntil → HomeScreen`
- Not dismissible via back button or barrier tap (forces a choice)

### Dialog Structure

```
AlertDialog
  backgroundColor: darkSurface (#10141B)
  shape: RoundedRectangleBorder(borderRadius: 20)
  contentPadding: EdgeInsets.all(24)

  content: Column
    Icon(Icons.palette_outlined, size: 48, color: cs.primary)
    SizedBox(height: 16)
    Text "Choose your experience" — Poppins 20px SemiBold textMain, center
    SizedBox(height: 8)
    Text "Pick a theme. You can change this later in Settings." — Inter 14px textSecondary, center
    SizedBox(height: 24)
    _ThemeChoiceCard — Dark Mode
    SizedBox(height: 12)
    _ThemeChoiceCard — Light Mode
```

### _ThemeChoiceCard

Each choice is a selectable card, not a plain button. Tapping it immediately commits and closes.

```
GestureDetector(onTap: () => _selectTheme(ThemeMode.dark))
  GlassContainer
    padding: EdgeInsets.symmetric(horizontal: 16, vertical: 16)
    borderRadius: 14
    color: (selected) ? cs.primary.withValues(alpha: 0.15) : glassBg
    borderColor: (selected) ? cs.primary : glassBorder
    child: Row
      Icon — Dark: Icons.dark_mode_outlined / Light: Icons.light_mode_outlined
             size: 24, color: (selected) cs.primary else textSecondary
      SizedBox(width: 12)
      Column
        Text mode name — Poppins 15px SemiBold (selected: textMain, else textSecondary)
        Text description — Inter 14px textSecondary
      Spacer
      if (selected) Icon(Icons.check_circle_rounded, color: cs.primary, size: 20)
```

Card descriptions:
- Dark Mode: `'Optimised for low-light use'`
- Light Mode: `'Clean, high-contrast display'`

No "Confirm" button. Tapping a card calls `_selectTheme()` which:
1. Calls `ThemeService.setThemeMode(mode)` (existing ChangeNotifier — propagates instantly)
2. Saves `prefs.setBool('theme_selected', true)` + `prefs.setString('theme_mode', 'dark'|'light')`
3. Writes `users/{uid}.update({'themeMode': 'dark'|'light'})` (fire-and-forget — no await in UI path)
4. Calls `Navigator.pop(context)` — dialog closes, login flow continues

### No Cancel Path
The dialog has no cancel button and is not dismissible. The user must choose. This is intentional — a theme preference is required before home screen entry.

## Surface 5b: Form Validation Feedback Conventions

These conventions apply to every `TextFormField` in Phase 02.1. They extend the existing `_FS` state machine used in `register_screen.dart` to the login screen's new Form widget.

### Inline Validation (Register Screen — existing _FS pattern, extended)

| State | Border color | Suffix icon | Error text |
|-------|-------------|-------------|------------|
| `pristine` | `darkBorder` (#21262D) | none | none |
| `checking` | `darkBorder` | `CircularProgressIndicator` (size 16, strokeWidth 2) | none |
| `valid` | `Colors.green.shade400` (1.5px) | `Icons.check_circle_outline_rounded` (green) | none |
| `invalid` | `cs.error` (1.5px) | `Icons.error_outline_rounded` (cs.error) | error string at 14px cs.error below field |

Error text animation: `AnimatedSwitcher` with 150ms fade. Do not use abrupt setState shows.

### Submit-time Validation (Login Screen — new Form pattern)

- On `_formKey.currentState!.validate()` call, all `TextFormField` validators fire simultaneously.
- Each field with a failing validator shows its error message inline below the field.
- No error banner replaces inline errors — the existing `_errorMessage` variable is retired.
- Firebase auth errors (wrong password, user not found) are shown in the `AnimatedSwitcher` error area between the form and the Login button (not below individual fields).

### Password Visibility Toggle
- Both Login and Register screens have `obscureText` toggle on password fields.
- The same convention applies to Confirm Password on Register.
- Icon: `Icons.visibility_off_outlined` (obscured) / `Icons.visibility_outlined` (visible), size 20.
- `IconButton` splash radius: 16px (contained within field border).
- Color: `textSecondary` (#8B949E) at rest. Does NOT change on toggle — only the icon changes.

### Required Field Indicators
No asterisk or "required" label. Fields are assumed required unless labelled optional. Login has no optional fields. Register has no optional fields in scope for this phase.

## Avatar Placeholder Convention

For Google-signed-in users and any user without a `photoURL`:

```dart
UserAvatar(username: displayName ?? username ?? uid.substring(0, 1))
```

The existing `UserAvatar` widget in `shared_widgets.dart` handles the initial-letter fallback — `username[0].toUpperCase()` in a `CircleAvatar` with `cs.primary.withValues(alpha: 0.10)` background and `cs.primary` text. No change to the widget is required.

When `photoURL` is available (Google users): wrap `UserAvatar` in a check — if `photoURL != null`, render `CircleAvatar(backgroundImage: NetworkImage(photoURL))` with the same border decoration as `UserAvatar`. If network load fails, fall back to initial-letter variant silently.
