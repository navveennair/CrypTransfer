# Phase 02.1: Identity & Networking — Context

**Gathered:** 2026-04-22
**Status:** Ready for planning
**Source:** User specification

<domain>
## Phase Boundary

Upgrade the Identity and Networking modules to professional standards. This phase delivers:
- Google Sign-In integration on Login/Register screens
- A `friendships` Firestore collection replacing the search-only friend model
- A "My Connections" screen with Disconnect capability
- A first-login theme onboarding overlay (Dark/Light choice)
- Standardized Login/Register form validation and password toggles

This phase does NOT touch the crypto transfer flow, SessionManager, or encryption services.

</domain>

<decisions>
## Implementation Decisions

### Google Authentication
- Integrate `google_sign_in` Flutter package
- Add "Continue with Google" button to both Login and Register screens
- Firebase Auth flow: `GoogleSignIn().signIn()` → get `GoogleSignInAccount` → get `GoogleSignInAuthentication` → create `GoogleAuthCredential` → `FirebaseAuth.instance.signInWithCredential()`
- On first Google sign-in: create a `users/{uid}` Firestore document with `email`, `displayName`, `photoURL`, `createdAt`, `isAdmin: false`, `isReadyToReceive: false`
- Existing email/password users are NOT affected

### Friendships Collection
- Replace search-only friend model with a `friendships/{docId}` Firestore collection
- Schema: `{ participants: [uid1, uid2], status: "pending"|"accepted"|"blocked", createdAt: Timestamp }`
- `docId` = deterministic: `min(uid1,uid2)_max(uid1,uid2)` to prevent duplicate documents
- Query pattern: `where('participants', arrayContains: currentUser.uid).where('status', isEqualTo: 'accepted')` for friends list
- Send friend request: create doc with `status: pending`, `requesterId: currentUser.uid`
- Accept/reject: update `status` field
- Block: update `status: blocked`

### My Connections Screen
- New screen: `lib/presentation/connections/connections_screen.dart`
- Shows list of accepted friends (query friendships where participants arrayContains uid AND status==accepted)
- Each friend row: avatar/username + "Disconnect" button
- Disconnect action:
  1. Delete `friendships/{docId}`
  2. Batch-delete all `rsa_key_transfers` docs where `fromUserId == currentUid && toUserId == friendUid` OR vice versa
  3. Show confirmation SnackBar
- Navigation: add entry in home screen / sidebar drawer

### Theme Onboarding Overlay
- Trigger: ONLY on first login after registration OR if `shared_preferences` key `theme_selected` is absent
- Check on login success: `prefs.getBool('theme_selected') ?? false`
- UI: full-screen overlay or `showDialog` — "Choose your experience: Dark Mode or Light Mode?"
- On selection:
  1. Save `prefs.setBool('theme_selected', true)` and `prefs.setString('theme_mode', 'dark'|'light')`
  2. Write `themeMode: 'dark'|'light'` to `users/{uid}` Firestore doc
  3. Update app-level theme state immediately (use a `ValueNotifier<ThemeMode>` or `ChangeNotifier`)
- App reads preference on startup via `shared_preferences`; Firestore write is fire-and-forget

### Form Validation
- Email: `RegExp(r'^[^@]+@[^@]+\.[^@]{2,}')` check in validator
- Password strength: minimum 8 characters, at least one letter and one digit
- Password fields: add `obscureText` toggle with eye icon (`IconButton` in `suffixIcon`)
- Use `GlobalKey<FormState>` + `Form` widget with `validator` callbacks (already uses Material forms)
- Apply to both `lib/presentation/auth/login_screen.dart` and `lib/presentation/auth/register_screen.dart`

### Claude's Discretion
- Friend request UI placement (could be in search results or a dedicated "Add Friend" screen) — implement inline in existing search/home flow
- Avatar placeholder when no `photoURL` — use first letter of username in a colored circle
- Firestore rules update for `friendships` collection — add read/write rules scoped to participants

</decisions>

<specifics>
## Specific Requirements from User

**Firestore friendships schema (exact):**
```
friendships/{docId}
  participants: [uid1, uid2]
  status: "pending" | "accepted" | "blocked"
  createdAt: Timestamp
```

**Disconnect must:**
1. Delete the `friendships` document
2. Delete shared handshake history (`rsa_key_transfers` docs for that pair)

**Theme onboarding:**
- Shows ONLY on first login after registration or if no preference saved
- "Dark Mode or Light Mode?" choice
- Saves to Firestore + `shared_preferences`
- Theme changes instantly

**Google Sign-In:**
- Works on Login AND Register screens
- Creates `users` doc on new account

</specifics>
