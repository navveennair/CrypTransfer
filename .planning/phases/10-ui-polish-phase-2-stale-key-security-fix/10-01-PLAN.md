<objective>
Restore the three-line stale-key invalidation guard in `SenderScreen._onHandshakeUpdate` that was
dropped in WIP commit `580616d` after Phase 09 verification. This is a security regression: without
the guard, if the receiver closes and reopens their mailbox (regenerating their RSA keypair), the
sender holds an `_encryptedAESKey` already encrypted to the OLD key — and the receiver cannot
decrypt it, causing a silent transfer failure with no user notification.

Purpose: Close ASVS V3 Session Management + V6 Cryptography gap — stale AES key must be wiped
and re-encryption required whenever the receiver's RSA public key changes mid-session.

Output: Three code blocks inserted surgically into `lib/presentation/sender/sender_screen.dart`,
preserving all additions from commit 580616d (`_everConnected`, `isReconnect` SnackBar).
</objective>

|----------|-------------|
| Firestore stream → SenderScreen | Handshake doc updates arrive from Firestore; publicKey field value originates from ReceiverScreen |
| compute() isolate → main isolate | RSA-encrypted AES key returned from isolate; main isolate state may have changed during compute |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Spoofing | `_onHandshakeUpdate` — stale `_encryptedAESKey` after receiver key rotation | mitigate | Restored D-01/D-02/D-03 guard: capture `previousPublicKey` before `setState`, compare after, wipe `_encryptedAESKey` via `_wipeSensitiveData()` if key changed — prevents AES key encrypted to wrong recipient key from being uploaded |
| T-10-02 | Tampering | `_onHandshakeUpdate` — guard fires during active `compute()` isolate | mitigate | D-02 mid-flight guard (`if (_encrypting || _encryptingKey) return;`) placed after `_checkTofuStatus` — prevents wipe racing with in-flight encryption |
| T-10-03 | Information Disclosure | `_wipeSensitiveData()` called during stale-key detection | accept | `_wipeSensitiveData()` zeros `_aesKey`, `_iv`, `_encryptedBytes`, `_encryptedAESKey` Uint8List buffers via `fillRange(0)`; does not affect `_selectedReceiverPublicKeyJson` (public key, not secret); acceptable |
