## Component Inventory — Phase 6 Additions

This section catalogs the new widgets and state conditions introduced by this phase. Each entry includes the Flutter widget tree, color, and interaction behavior.

### 1. _WaitingForReceiverWidget (SenderScreen — Step 0 expanded content)

Replaces the content of Step 0's `child:` parameter while `_receiverReady == false` AND `_receiverSelected == true`.

**States it replaces/extends:**
- While `!_receiverSelected`: show existing `_WaitingForConnectionWidget` (no change).
- While `_receiverSelected && !_receiverReady`: show `_WaitingForReceiverWidget` (NEW).
- While `_receiverSelected && _receiverReady`: show existing `_ConnectedBadge` (no change).

**Widget structure:**

```
Center
  └── Column (mainAxisSize: min)
        ├── SizedBox(height: 16)
        ├── ScaleTransition(scale: 0.9→1.1, 1500ms, repeat reverse)
        │     └── FadeTransition(opacity: 0.5→1.0, 1500ms, repeat reverse)
        │           └── Container(
        │                 shape: circle
        │                 padding: all(20)
        │                 color: cs.primary.withValues(alpha: 0.1)
        │                 border: cs.primary.withValues(alpha: 0.2), width: 2
        │               )
        │                 └── Icon(Icons.hourglass_top_rounded, color: cs.primary, size: 32)
        ├── SizedBox(height: 20)
        ├── Text(
        │     "Waiting for Receiver to prepare secure vault…"
        │     style: GoogleFonts.poppins(fontWeight: w600, fontSize: 14)
        │     textAlign: center
        │   )
        ├── SizedBox(height: 8)
        ├── Text(
        │     "Receiver must open the secure inbox to continue."
        │     style: TextStyle(fontSize: 12, color: cs.onSurfaceVariant)
        │     textAlign: center
        │   )
        ├── SizedBox(height: 16)
        └── _CountdownTimer (see below)
              └── SizedBox(height: 16)
```

**AnimationController:** vsync: SingleTickerProviderStateMixin, duration 1500ms, repeat(reverse: true). Same parameters as the existing `_WaitingForConnectionWidget` — reuse the pattern exactly.

**Icon:** `Icons.hourglass_top_rounded` — differentiates from the connection-wait icon (`Icons.wifi_tethering_rounded`) to signal that a connection exists but readiness is pending.

### 2. _CountdownTimer (inline child of _WaitingForReceiverWidget)

Countdown from 60 to 0 seconds. Displayed inside the Step 0 waiting card, below the subtitle text.

**Display format:** `MM:SS` — e.g., `01:00`, `00:45`, `00:00`. Two digits for minutes, two for seconds, colon separator. Rationale: consistent width prevents layout reflow as digits change; `01:00` is clearer than "60 seconds remaining" in a compact card.

**Widget structure:**

```
GlassContainer(
  padding: symmetric(horizontal: 16, vertical: 8)
  color: cs.primary.withValues(alpha: 0.07)
  borderColor: cs.primary.withValues(alpha: 0.15)
  borderRadius: 12
)
  └── Row(mainAxisAlignment: center)
        ├── Icon(Icons.timer_outlined, size: 16, color: cs.primary)
        ├── SizedBox(width: 8)
        └── Text(
              "00:45"   ← formatted from _secondsRemaining
              style: GoogleFonts.poppins(
                fontSize: 20
                fontWeight: FontWeight.w700
                color: cs.primary
              )
            )
```

**Timer implementation:** `Timer.periodic(Duration(seconds: 1), ...)` decrementing a `_secondsRemaining` int from 60. Cancelled in `dispose()` and when `receiverReady` fires. When `_secondsRemaining <= 0`, trigger safety eject (see Interaction Contract — Safety Timer).

**State hosting:** Timer state hosted on `_SenderScreenState` (not a separate StatefulWidget) to share lifecycle with the screen's `dispose()` and `_onHandshakeUpdate` callbacks. Two new fields: `Timer? _readinessTimer` and `int _secondsRemaining = 60`.

### 3. Steps 1–4 visibility gate (SenderScreen)

**Current behavior:** Steps 1–4 are shown with `AnimatedOpacity(opacity: _receiverSelected ? 1.0 : 0.4)` plus `onPressed: _receiverSelected ? handler : null`.

**Phase 6 change (D-04):** Steps 1–4 are HIDDEN (not just dimmed) while `_receiverReady == false`. Use conditional rendering: wrap Steps 1–4 column children with `if (_receiverReady) ...`. When `_receiverReady` becomes true, use `AnimatedOpacity` fade-in over 300ms. Implementation pattern:

```dart
// New state field
bool _receiverReady = false;

// In build():
// Steps 1-4 wrapped in:
AnimatedOpacity(
  opacity: _receiverReady ? 1.0 : 0.0,
  duration: const Duration(milliseconds: 300),
  child: IgnorePointer(
    ignoring: !_receiverReady,
    child: Column(...steps 1-4...)
  ),
)
```

`IgnorePointer` ensures the hidden steps cannot receive taps even at opacity 0.0 (avoids invisible tap targets).

## Interaction Contract

### Sender flow — state machine

| State | Step 0 child | Steps 1–4 | Timer |
|-------|-------------|-----------|-------|
| `!_receiverSelected` | _WaitingForConnectionWidget (existing) | Hidden (opacity 0.0) | Not started |
| `_receiverSelected && !_receiverReady` | _WaitingForReceiverWidget (NEW) | Hidden (opacity 0.0) | Running (60s countdown) |
| `_receiverSelected && _receiverReady` | _ConnectedBadge (existing) | Visible (opacity 1.0, AnimatedOpacity 300ms) | Cancelled |

### _onHandshakeUpdate — additions to existing handler

```
_onHandshakeUpdate fires (QuerySnapshot arrives)
  ├── snap.docs.isEmpty → _revertToWaiting() + cancel timer (existing + timer cancel)
  └── snap.docs.first → parse existing fields (receiverId, publicKey, receiverUsername)
        ├── parse receiverReady = doc['receiverReady'] as bool? ?? false
        └── if (publicKey valid && receiverId valid)
              ├── setState: _receiverId, _receiverUsername, _selectedReceiverPublicKeyJson (existing)
              ├── if (!_receiverReady && receiverReady == true)
              │     → _onReceiverBecameReady() — cancel timer, show green SnackBar, setState _receiverReady = true
              └── else if (_receiverReady != receiverReady)
                    → setState: _receiverReady = receiverReady
```

### Safety timer trigger conditions

| Trigger | Action |
|---------|--------|
| `snap.docs.isEmpty` while `_receiverReady == false` | Cancel timer. Call `_ejectToHomeScreen()`. Show red SnackBar before navigation. |
| `_secondsRemaining` decrements to 0 | Cancel timer. Call `_ejectToHomeScreen()`. |
| `receiverReady` becomes `true` | Cancel timer. Show green SnackBar. Proceed normally. |
| Screen `dispose()` | Cancel timer unconditionally. |

`_ejectToHomeScreen()` method:
1. Show red SnackBar: "Session Terminated — receiver closed the session."
2. Call `_wipeSensitiveData()`.
3. `Navigator.pushAndRemoveUntil(context, MaterialPageRoute(builder: (_) => HomeScreen()), (_) => false)`.

### Receiver flow — receiverReady write

In `_onSenderSelected()`, after `await _connService.selectSenderHandshake(...)` succeeds and before the final `setState`:

```
await _connService.selectSenderHandshake(...)
  → on success: setState(_handshakeDone = true, _handshaking = false)
  → then: _writeReceiverReady()

_writeReceiverReady():
  try:
    await KeyRepository.setReceiverReady(handshakeDocId)
  catch (e):
    showSnackBar: "Failed to signal readiness — tap to retry." + Retry action
```

The `handshakeDocId` is the deterministic ID `${receiverUid}_${senderUid}` used in `publishRSAPublicKey()` and `selectSenderHandshake()`.

### Firestore security rule requirement

The existing `handshakes/` rule allows update for `resource.data.receiverId == request.auth.uid` OR `resource.data.senderId == request.auth.uid`. The receiver is `receiverId` on the handshake doc. The `receiverReady` field update is a targeted update (single field added to existing doc). This must be validated: the plan must confirm the existing update rule covers this write, or add a targeted field allowance if needed. Based on current rules, the receiver (as `receiverId`) already has update permission — no rule change required unless the planner identifies a restriction to specific fields.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (SenderScreen Step 0 — waiting state heading) | "Waiting for Receiver to prepare secure vault…" |
| Waiting state subtitle | "Receiver must open the secure inbox to continue." |
| Success SnackBar (receiver ready) | "Secure channel established. Receiver is ready." |
| Safety timer / eject SnackBar | "Session Terminated — receiver closed the session." |
| Receiver ready-write failure SnackBar | "Failed to signal readiness — tap to retry." |
| Retry action label | "Retry" |
| Countdown label (inside timer container — not shown as text, only MM:SS digits) | MM:SS format only; no surrounding label text needed |

Copywriting rules:
- All SnackBar copy is sentence case, ends with a period.
- No exclamation marks.
- Error messages name the problem first ("Failed to signal readiness") then the path forward ("tap to retry").
- "Secure vault" and "secure inbox" are the established UX vocabulary for the receiver's cryptographic environment — do not substitute "mailbox" or "session" in user-facing strings.

Empty state: Not applicable to this phase. The waiting widget IS the empty/loading state for the readiness gate — it is fully specified above.

Destructive actions in this phase: None initiated by the user. The safety timer eject is automatic (not a user-triggered destructive action requiring confirmation). No confirmation dialog is needed.
