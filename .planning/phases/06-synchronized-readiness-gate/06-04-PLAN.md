<objective>
Close three defects that block Phase 6's synchronized readiness gate from working reliably:

- CR-01: `_onHandshakeUpdate` ejects the sender to HomeScreen on the Firestore stream's cold-start empty snapshot, breaking all SenderScreen entry paths.
- WR-01: `keyPayload` in `selectSenderHandshake()` omits `'receiverReady': false`, so the `batch.update` path for returning pairs leaves the prior session's `receiverReady: true` on the doc — bypassing the gate on every second session.
- WR-03: When `receiverReady` reverts to `false` after the gate was unlocked, the current `else if` branch only sets the flag without restarting the timer, leaving the sender frozen with a non-ticking countdown.

Purpose: Make the readiness gate reliable across all entry paths (cold-start, pre-filled, returning pairs, and post-unlock reverts).
Output: Modified `sender_screen.dart` (stream-settled guard + revert fix) and `key_repository.dart` (keyPayload reset).
</objective>
