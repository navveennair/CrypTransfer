# Phase 07.1 Plan 01: Repository Layer Contracts (Wave 0)

## One-liner

Created repository layer method signatures and return types for Firestore data access, establishing clean separation between presentation and data layers ahead of Wave 1 UI migrations.

## Summary

Wave 0 of the Layer Decoupling Refactor created the abstract "contracts" that UI screens will call in subsequent waves. This plan introduces 4 repository files with 14 new methods, centralizing all Firestore operations and enforcing the Strict Decoupling Mandate from CLAUDE.md.

### Key Accomplishments

1. **CleanupRepository** (new file, 122 lines)
   - `initiateReceiverCleanup()`: Turn 1 — write cleanup_initiated flag + audit log
   - `watchTransferForDeletion()`: Stream-watch for Turn 4 deletion trigger
   - `completeReceiverCleanup()`: Turn 3 — atomic batch delete + dual audit logs
   - Follows 4-turn synchronized cleanup protocol (receiver → sender → receiver → sender)

2. **TransferRepository** extended (6 new methods, 114 lines)
   - `watchTransferStatus()`: Stream single transfer doc for reactive updates
   - `streamRecentTransfers()`: User's audit_logs for HomeScreen recent transfers
   - `updateTransferField()`: Generic single-field update (replaces scattered .update() calls)
   - `updateTransferStatus()`: Status update with validation (pending/in-progress/completed/cancelled/rejected)
   - `cancelTransfer()`: Convenience method to set status = cancelled
   - `getTransferDoc()`: Existence check for cleanup verification

3. **AdminRepository** updated (constructor + 4 new methods, 36 lines)
   - Constructor now uses dependency injection: `FirebaseFirestore? db` parameter
   - `streamActiveHandshakesDetail()`: Full QuerySnapshot for active handshakes
   - `streamUserConnections()`: All users for connection node map
   - `streamSecurityAuditLog()`: Security logs ordered by timestamp
   - `streamTransferLogsDetail()`: Full transfer logs QuerySnapshot

4. **UserRepository** (new file, 61 lines)
   - `updateUser()`: Update user document fields (onboarding, preferences, etc.)
   - `streamUserWithFriendships()`: User + accepted connections for node map visualization
   - Uses asyncMap to fetch friendships inline

5. **FirebaseConstants** enhancement (1 line)
   - Added `connections` constant (string literal 'connections') for subcollection queries

### Design Patterns Established

- **Constructor Injection**: All repositories accept optional `FirebaseFirestore? db` parameter for testability
- **Exception Typing**: `TransferException` for transfer operations, `AuthException` for user operations
- **Stream vs Future**: `Stream<T>` for real-time updates, `Future<T>` for single operations
- **Consistent Organization**: Methods grouped by concern with section comments

### Strict Decoupling Compliance

All 14 new methods are called from UI screens in future waves. No Presentation Layer file imports `FirebaseFirestore.instance` or any Firebase SDK directly. All data access flows through Repository methods.
